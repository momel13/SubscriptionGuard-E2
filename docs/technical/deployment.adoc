Dieses Dokument beschreibt, wie der SubscriptionGuard-Prototyp lokal gestartet,
konfiguriert und fuer einen Live-Test gegen Supabase geprueft wird. Technische
Entscheidungen rund um Architektur und Datenhaltung sind im
link:architecture.adoc[Architekturdokument] dokumentiert.

== Voraussetzungen

Fuer das Ausfuehren des Prototyps muessen folgende Tools lokal installiert sein:

* **Node.js** (empfohlen: Version 18 LTS oder neuer)
* **Webbrowser** mit aktivierter JavaScript-Unterstuetzung
* **Git** zum Klonen oder Aktualisieren des Repositorys
* Zugriff auf die privaten Supabase-Konfigurationswerte fuer lokale Live-Tests

IMPORTANT: Echte `.env`-Werte, Tokens und insbesondere der
`SUPABASE_SERVICE_ROLE_KEY` duerfen nicht committed und nicht in Screenshots oder
oeffentlichen Chats geteilt werden.

== Lokale Ausfuehrung des Live-Prototyps

=== 1. Repository aktualisieren

[source,powershell]
----
git checkout main
git pull
----

=== 2. Backend-Abhaengigkeiten installieren

Das muss normalerweise nur einmal pro Rechner oder nach Aenderungen an
`package.json` / `package-lock.json` ausgefuehrt werden.

[source,powershell]
----
cd src\SubGuard-Prototyp\backend
npm.cmd install
----

=== 3. Lokale `.env` vorbereiten

Die lokale Datei muss hier liegen:

[source,text]
----
src/SubGuard-Prototyp/backend/.env
----

Sie basiert auf `src/SubGuard-Prototyp/backend/.env.example` und enthaelt lokal
die echten Werte:

[source,dotenv]
----
PORT=5001
SUPABASE_URL=https://<project-ref>.supabase.co
SUPABASE_ANON_KEY=<publishable-key>
SUPABASE_SERVICE_ROLE_KEY=<secret-key>
SUPABASE_DEMO_EMAIL=demo@subscriptionguard.app
SUPABASE_DEMO_PASSWORD=<demo-password>
SUPABASE_DEMO_USER_NAME=Demo User
----

Der Service-Role-Key bleibt ausschliesslich im Backend. Er wird im Prototyp nur
verwendet, um den Demo-User und das Profil in `public.users` lokal fuer den
Live-Test vorzubereiten.

=== 4. Backend starten

[source,powershell]
----
npm.cmd run dev
----

Das Backend laeuft standardmaessig auf:

[source,text]
----
http://localhost:5001
----

Das Terminal muss waehrend des Tests offen bleiben.

=== 5. Frontend oeffnen

Die Datei `src/SubGuard-Prototyp/frontend/index.html` kann im Browser geoeffnet
werden, z. B. ueber "Reveal in File Explorer" und Doppelklick auf die Datei.

Das Frontend ruft danach das lokale Backend auf `http://localhost:5001` auf. Beim
Start wird `POST /api/auth/demo` verwendet, um einen Demo-Access-Token zu erhalten.

== Datenquellenmodi

[cols="1,3", options="header"]
|===
| Modus | Bedeutung

| `Live Express Backend (Supabase)`
| Das Frontend nutzt das lokale Express-Backend. Der Demo-Login liefert einen echten
Supabase Access Token. Abo-Daten werden ueber das Backend in Supabase gespeichert
und unterliegen RLS.

| `Live Express Backend (lokaler Demo-Modus)`
| Das Backend ist erreichbar, konnte aber keinen gueltigen Supabase-Demo-Login
vorbereiten. Speichern wird lokal im Backend-Demo-Modus simuliert.

| `Mock-Fallback`
| Das Backend ist nicht erreichbar oder die Initialisierung ist fehlgeschlagen. Das
Frontend verwendet lokale Mock-Daten.
|===

== Verifikation und Funktionspruefung

=== Live-Test: Abo erfassen

. Backend mit `npm.cmd run dev` starten.
. `frontend/index.html` im Browser oeffnen.
. Pruefen, dass das Datenquellenlabel `Live Express Backend (Supabase)` anzeigt.
. Ein Test-Abo anlegen, z. B. "Live Demo Gym".
. In Supabase im Table Editor die Tabelle `subscriptions` oeffnen und aktualisieren.

Erwartetes Ergebnis: Das neue Abo erscheint als Datensatz in `subscriptions` und
ist dem Demo-User ueber `user_id` zugeordnet.

=== Fehlerhilfe

[cols="1,3", options="header"]
|===
| Beobachtung | Moegliche Ursache / Massnahme

| `Missing Supabase`
| Die `.env` fehlt, liegt im falschen Ordner oder enthaelt keine gueltigen
Supabase-Werte.

| `Mock-Fallback`
| Das Frontend erreicht das Backend nicht. Backend starten, Port `5001` pruefen
und Browser neu laden.

| `lokaler Demo-Modus`
| Backend laeuft, aber Demo-Login oder Service-Role-Vorbereitung ist fehlgeschlagen.
`.env` pruefen und Backend neu starten.

| PowerShell blockiert `npm run dev`
| Unter Windows `npm.cmd run dev` verwenden.
|===
