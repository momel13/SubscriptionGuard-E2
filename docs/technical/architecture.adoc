*Externe Schnittstellen des Gesamtsystems:*

[cols="1,1,3,2", options="header"]
|===
| Schnittstelle | Typ | Beschreibung | Protokoll / Format

| **Nutzer-Schnittstelle**
| Mensch-Maschine
| Ermöglicht die Interaktion mit dem Dashboard, das Erfassen von Abonnements sowie Datei-Uploads.
| HTTPS / JSON & FormData

| **Supabase Auth**
| Externes System
| Übernimmt die sichere Verwaltung von Nutzerkonten und stellt Token (JWT) bereit.
| HTTPS / JWT

| **PostgreSQL / Supabase**
| Persistenz
| Zentraler Cloud-Speicher für alle relationalen Daten (Nutzer inkl. Budget, Abos, Kategorien).
| SQL / pg-Treiber (TLS)

| **Push-Dienste**
| Externes System
| Brücke zu nativen Benachrichtigungssystemen für Kündigungswarnungen.
| HTTPS / OS-spezifisch
|===

== 3. Architekturtreiber ableiten

=== 3.1 Ziel und Quellen
Dieses Dokument beschreibt die Architektur von SubscriptionGuard als Gesamtsystem auf Basis des Funktionskatalogs (F1-F8), der Use Cases (UC1-UC5) und der technischen ADRs.

=== 3.2 Architektur-Anforderungen aus dem Produktkonzept

[cols="3,6,2",options="header"]
|===
|Anforderung |Technische Konsequenz |Entscheidung

|*Datensicherheit*
|Sensible Finanzdaten erfordern Transportverschlüsselung (HTTPS) und strikte Mandantentrennung via RLS.
|ADR-002

|*CSV-Import*
|Rechenintensives Parsing muss asynchron/serverseitig laufen, um UI-Freezes zu verhindern.
|ADR-005

|*Cross-Platform*
|Cross-Platform-Stack (React/Vite als PWA) zur Code-Teilung zwischen Web und Mobile.
|ADR-001

|*Wartbarkeit*
|Datenbankgetriebene Kategorien statt Hardcoding ermöglichen schnelle Erweiterungen.
|—
|===

=== 3.3 Fachliche Architekturtreiber

[cols="1,2,3,3",options="header"]
|===
|Quelle |Anforderung |Architektur-Konsequenz |Betroffene Bausteine

|F1/F2
|Abo- & Fristenverwaltung
|CRUD-Funktionen und Scheduler zur Fristenprüfung.
|Frontend, Backend, DB

|F3
|Kostenanalyse
|Aggregationen in SQL/Backend; Visualisierung im UI.

|F6

|Parsing und Mustererkennung im Backend.
|`multer`, `csv-parse`, Import-Wizard

|F7

|Nutzerbezogenes Ausgabenlimit und Statusüberwachung.
|Attribut `monthly_budget` in `users`
|===

=== 3.4 Qualitätsanforderungen

[cols="1,3,3",options="header"]
|===
|Treiber |Begründung |Architekturantwort

|Einfachheit
|Zielgruppe sind Studierende; intuitive Bedienung nötig.
|Mantine UI, geführte Wizards.

|Datenschutz
|Finanzdaten sind hochsensibel.
|EU-Region Supabase, kein 3rd-Party Tracking.

|API-Sicherheit
|Konsistenz zwischen FE und BE.
|Shared TypeScript-Types.
|===
