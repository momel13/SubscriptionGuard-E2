== 3. Wichtigste Lernergebnisse aus Sprint 3

[cols="1,3", options="header"]
|===
| Kriterium | Ihre Antwort

| Sicherheit nicht gegen Funktionalität tauschen: Der Durchstich lief zunächst nur mit deaktivierter RLS. Jetzt bleibt RLS aktiv, das Backend nutzt den Nutzer-JWT, Policy `user_id = auth.uid()` (https://github.com/momel13/SubscriptionGuard-E2/issues/84[#84], PR https://github.com/momel13/SubscriptionGuard-E2/pull/89[#89]/https://github.com/momel13/SubscriptionGuard-E2/pull/90[#90]).

| Ein schmaler, vollständiger vertikaler Schnitt ist wertvoller als mehrere halbfertige Funktionen: nur „Create" fertig, „Übersicht" (https://github.com/momel13/SubscriptionGuard-E2/issues/3[#3]) und „Bearbeiten/Löschen" (https://github.com/momel13/SubscriptionGuard-E2/issues/37[#37]) bewusst verschoben.

| Erkenntnis 3
| Lokale Lauffähigkeit hängt an der Auth-Verfügbarkeit: Supabase Auth war durch Rate-Limit blockiert (PR https://github.com/momel13/SubscriptionGuard-E2/pull/83[#83]) → Backend-Demo-Fallback; echter Live-Test gegen Supabase dennoch nachgewiesen.
