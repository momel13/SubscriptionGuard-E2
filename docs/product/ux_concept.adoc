== Personas

_Personas sind fiktive, aber realitätsbasierte Beschreibungen typischer Nutzender.
Sie helfen dem Team, Entscheidungen konsequent aus Nutzerperspektive zu treffen.
Personas sollten auf echten Nutzerinterviews oder Beobachtungen basieren — nicht
auf Annahmen allein._

_Hinweis: Im link:product_concept.adoc[docs/product/product_concept.adoc] werden Zielgruppen nur benannt. Hier werden sie als Personas ausgearbeitet._

=== Aktuelle Situation (ohne das Produkt)

_Wie lösen die Nutzenden ihr Problem heute? Diese Beschreibung zeigt, was das Produkt
verbessern soll — und macht den Mehrwert explizit._

[Derzeit verwalten Studierende und junge Erwachsene ihre Abonnements oft gar nicht, über unübersichtliche Kontoauszüge oder verstreute E-Mails. Dies führt dazu, dass Kündigungsfristen im Alltag vergessen werden und ungewollte Kosten durch automatische Verlängerungen entstehen. Das manuelle Ermitteln der monatlichen Fixkosten oder Einsparpotenziale ist zeitaufwendig und führt zu einem hohen "Mental Load".]

=== Interaktionsfluss: Abo manuell anlegen (UC1)

_Dieser Fluss zeigt, wie ein Nutzer manuell ein neues Abonnement erfasst und wie das System darauf reagiert, um zukünftige Erinnerungen sicherzustellen [cite: 967-986]._

[plantuml, abo-anlegen-flow, svg]
....
@startuml
skinparam monochrome true
skinparam defaultFontSize 13

start
:Nutzer tippt "Abo hinzufügen";
:System zeigt Eingabeformular;
:Nutzer gibt Name, Kosten, Intervall etc. ein;
if (Eingaben gültig?) then (nein)
  :Fehlermeldung anzeigen;
  stop
else (ja)
  :Abo in Datenbank speichern;
  :Monatliche Kosten berechnen;
  if (Kündigungsfrist vorhanden?) then (ja)
    :Erinnerung im System erstellen;
  endif
  :Abo-Liste aktualisieren;
endif
stop
@enduml
....

=== Interaktionsfluss: CSV-Import (UC4)

_Dieser Fluss beschreibt den Massenimport von Kontoauszügen, bei dem das System dem Nutzer die Arbeit abnimmt, wiederkehrende Muster zu erkennen [cite: 1019-1036]._

[plantuml, csv-import-flow, svg]
....
@startuml
skinparam monochrome true
skinparam defaultFontSize 13

start
:Nutzer wählt CSV-Datei aus;
if (Datei lesbar?) then (nein)
  :Fehlermeldung anzeigen;
  stop
else (ja)
  :System parst Datei;
  :Mustererkennung für Abos;
  if (Wiederkehrende Muster gefunden?) then (nein)
    :Meldung "Keine Abos erkannt";
    stop
  else (ja)
    :Vorschläge anzeigen;
    :Nutzer bestätigt/verwirft Vorschläge;
    :Bestätigte Abos automatisch anlegen;
    :Zusammenfassung anzeigen;
  endif
endif
stop
@enduml
....

=== Interaktionsprinzipien

_Vereinbarte UX-Regeln, die für das gesamte Produkt gelten. Jede Entscheidung wird begründet, damit sie nicht aus Unwissenheit verletzt wird._

[cols="2,3", options="header"]
|===
| Prinzip | Beschreibung & Begründung

| **Einfachheit (MVP-Fokus)**
| Reduziertes Interface ohne unnötige komplexe Finanz-Features. Begründung: Nutzer wollen eine schnelle Übersicht, kein Buchhaltungs-Tool.

| **Datenschutz durch Transparenz**
| Prominenter Hinweis auf lokale Datenspeicherung (Offline-First). Begründung: Reduziert Skepsis bei der Eingabe sensibler Finanzdaten.

| **Destruktive Aktionen werden immer bestätigt**
| Lösch- oder Stornieraktionen erfordern eine explizite Bestätigung durch die Nutzenden. Verhindert unbeabsichtigte Datenverluste.

| **Kernfunktionen sind mit einer Hand erreichbar**
| Primäre Aktionen (z. B. "Abo hinzufügen") befinden sich im unteren Bildschirmbereich (Daumenzone). Optimiert für einhändige Smartphone-Nutzung.
|===
